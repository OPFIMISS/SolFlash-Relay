# SolFlash Relay 0.6.4

Release date: 2026-08-09

## 中文

- 重做“接管 Haha 对话”：Relay 使用 OpenAI Codex App Server 在相同 `cwd` 创建真实、持久化、Codex 桌面可见的 Sol 对话，并设置可辨识标题。
- 新增顶部 `+` 普通任务入口：项目路径可选，可选择主策划/执行 Agent 与对应模型，填写需求、允许范围、约束、验收命令和是否返回主策划复审。
- 普通任务同样执行真实 `主策划规划 → 同路径新建执行 Agent 对话 → 可选主策划复审`；空路径会创建 Relay 托管目录。
- 新工作流为 `Sol 审查 → 原 Haha sessionId 执行 → 同一 Sol thread 复审`。只有 Sol 最终返回通过，Relay 才将整体任务标记为完成；需要返工时自动恢复原 Haha 会话继续执行。
- 面板明确显示 `Sol 审查中`、`Flash 执行中`、`Sol 复审中` 和 `Sol 验收完成`，A 对话显示真实 Codex `threadId`。
- 接管任务的补充要求会继续交给同一个 Sol thread，由 Sol 审查后生成下一条 Flash 指令。
- 修复 Codex MCP 重复 TOML section。安装会清除完整块和缺失 END 的孤立 Relay section，同时保留其中穿插的所有其他项目配置。
- 已真实验证 `gpt-5.6-sol` 读取 README 与 Git diff，创建的 App Server thread 能立即出现在 Codex 桌面任务列表；测试 thread 已归档。
- 已完成真实普通任务 E2E：Codex thread 与 Haha session 在同一路径分别新建，`deepseek-v4-flash` 写入证明文件，随后同一 Codex thread 复审通过；测试 Codex thread 已归档。

## English

- Rebuilds Haha adoption around a real persistent Codex App Server thread created with the exact project `cwd` and a visible desktop title.
- Adds a `+` task composer for ordinary work with an optional project path, planner/executor profiles and models, requirements, allowed scope, constraints, acceptance commands, and an optional final planner review.
- Ordinary tasks now use a real `planner design → new same-path executor conversation → optional planner verification` workflow. An empty path creates a Relay-managed workspace.
- The workflow is now `Sol review → original Haha sessionId execution → same Sol thread verification`. Relay reports completion only after Sol accepts the real changes; revision requests automatically resume the original Haha conversation.
- The dashboard exposes explicit Sol-review, Flash-execution, Sol-verification, and accepted states, including the real Codex `threadId` in conversation A.
- Additional guidance for an adopted task continues the same Sol thread instead of bypassing the planner and sending directly to Flash.
- Codex MCP installation repairs both complete and orphaned duplicate Relay TOML sections while preserving unrelated project configuration.
- A real `gpt-5.6-sol` App Server thread was verified to read README and Git diff and to appear in the Codex desktop task list; the probe thread was archived afterward.
- A real ordinary-task E2E created separate Codex and Haha conversations under one path, used `deepseek-v4-flash` to write a proof file, and returned to the same Codex thread for acceptance; the Codex probe was archived.
