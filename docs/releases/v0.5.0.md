# SolFlash Relay 0.5.0

## 中文

本版本重点解决“界面显示 Pro、Relay 任务没有回复”的可核验性与可靠性问题。

### 新功能

- 新增 `agent_run`：Sol 可以在一次 MCP 调用中派发任务并等待执行 Agent 的最终回复。
- 新增按绝对项目路径分组的工作台，以及同一任务内 A（策划）/ B（执行）上下双对话。
- 新增 Windows 完成/失败通知、任务栏未读 `1` 角标、点击通知定位任务和聚焦清除未读。
- 新增可见 Flash 自检，显式使用 `deepseek-v4-flash`，校验有效模型、非空回复和证明文件。
- GitHub 首页 README 改为中英双语，并加入桌面、设置和移动端截图。

### 修复

- 空 result 或无最终正文不再被误判为完成。
- 记录请求模型、执行 CLI 模型别名和 Provider 回报的有效模型。
- 检测旧版本 Relay daemon 占用端口，避免新版 UI 连接旧后端。
- 修复 Windows 上状态文件替换偶发 `EPERM`，避免任务已执行但回复无法保存。
- 后台通知同时使用 SSE 与低频状态校准，休眠或重连后仍能补发未读状态。

### 真实验证

- 可见 Haha 会话：`Visible Flash self-check`
- 请求模型：`deepseek-v4-flash`
- 有效模型：`deepseek-v4-flash`
- 最终回复：非空，包含 `FLASH_VISIBLE_OK`
- 证明文件：`.relay-data/visible-flash-proof/output.txt`

注意：Haha 中的 `Unknown skill: usage` 会话来自 Token Monitor 0.42.1 的 `/usage` 探测，不是 Relay 任务。它会继承 Haha 全局默认模型，因此可能显示 Pro 且没有模型回复。

## English

This release focuses on making model selection and executor replies verifiable and reliable, especially when Haha appears to show Pro or a task seems to return no response.

### Features

- Added `agent_run`, which dispatches work and waits for the execution Agent's final reply in one MCP call.
- Added project grouping by absolute path and a two-part A (planner) / B (executor) conversation workspace.
- Added Windows completion/failure notifications, a taskbar unread `1` badge, notification task focus, and focus-to-clear behavior.
- Added a visible Flash self-check that explicitly requests `deepseek-v4-flash` and validates the effective model, non-empty reply, and proof file.
- Reworked the GitHub README as a bilingual Chinese/English homepage with desktop, settings, and mobile screenshots.

### Fixes

- Empty or missing final results now fail explicitly instead of being marked completed.
- Relay records the requested model, executor CLI alias, and provider-reported effective model separately.
- Old Relay daemon port conflicts are detected before the new UI attaches to an outdated backend.
- Fixed intermittent Windows `EPERM` errors while replacing persisted task/settings files.
- Desktop notifications use SSE plus low-frequency reconciliation so unread state recovers after sleep or reconnects.
